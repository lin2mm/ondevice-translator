# 01 · 选型与模型清单（全部为 2026-09 核实数据）

## 1. 主力：Hy-MT2-1.8B（Apache-2.0）

| 项 | 值 | 来源 |
|---|---|---|
| 参数 / 架构 | 1.8B，`hunyuan_v1_dense`，纯 decoder-only | HF `tencent/Hy-MT2-1.8B` config |
| 语言 | 33 语 + 5 方言/民族语言变体（含简繁、粤语），1056 个方向 | 模型卡 |
| 许可证 | **Apache-2.0**（可商用、可闭源分发 App、需保留 LICENSE/声明） | `cardData.license: apache-2.0` + 仓库内 `LICENSE.txt` |
| 权重体积 | BF16 4077MB；GGUF **Q4_K_M 1133MB / Q6_K 1475MB / Q8_0 1909MB**；AngelSlim 量化 **1.25Bit 462MB / 2Bit 601MB** | HF blobs API 实测 |
| 质量口径 | 官方称 1.8B 整体优于微软/豆包等商用 API；1.5 系曾对标 Qwen3-32B、Tower-Plus-72B | 模型卡（厂商自述，需自建集复核） |
| 附带资产 | 官方给了**训练脚本目录**（LoRA/全参 SFT 配置齐全） → L4 自学习路线有官方工具链 | 仓库 `train/` 文件列表 |

**为什么它比 TranslateGemma 更适合本项目**：① 462MB vs 2.49GB（"最轻量"要求）；② Apache-2.0 vs Gemma Terms（后者条款多、且 HF repo 是 **gated**：必须登录接受条款才能下载 → 你的 App 不能直连 HF，用户也下不动，只能自己搬运托管）；③ 它原生支持"术语介入 / 上下文 / 风格 / 结构化保形"模板，正好是自学习和 UI 功能需要的钩子。

**官方推理参数**（不要自己乱调）：`temperature 0.7 / top_p 0.6 / top_k 20 / repetition_penalty 1.05`，无默认 system prompt。`core/prompt.py` 已按此实现，重试时降到 `0.3/0.8/40/1.08`。

## 2. 六类官方模板 → 产品功能映射（这就是 App 的差异化）

| 模板 | UI 功能 | 备注 |
|---|---|---|
| Default | 主翻译框、划词、分享扩展 | 中文方向用中文指令 + 中文语言名 |
| Terminology | 术语表（enforce/hint）、**自学习回灌** | 注入 `X 翻译成 Y` 行 |
| Style | "正式/口语/技术文档/邮件"风格条 | 一句话开关 |
| Personalization | 用户自定义规则（"公司名不译""人称用您"） | 存本地，逐条注入 |
| Delimiters | 表情/换行/分隔符保形（聊天翻译必开） | 自动检测分隔符密度 |
| Structured (JSON/YAML/HTML) | 整篇文档/配置翻译、字幕、Markdown | 强制"键名不动" |

`language` 必须写**全名**：`将以下文本翻译为 英语…` / `Translate the following text into Chinese…`。写 `zh→en` 代码会明显变差（小模型对指令很敏感）。

## 3. 备选与对照

| 方案 | 体积 | 许可 | 结论 |
|---|---|---|---|
| TranslateGemma 4B（Q4_K_M 2.49GB / IQ4_XS 2.28GB / Q3_K_M 2.10GB） | 2.3–2.5GB | Gemma Terms | 旗舰"质量档"可选下载；**不做默认**，gated + 体积超标 |
| Gemma 4 E2B `litert-community/gemma-4-E2B-it-litert-lm`（gpu 2.01GB） | 2.0GB | **Apache-2.0** | 通用助手（顺带做润色/摘要）时选它，纯翻译不如 Hy-MT2 |
| Hy-MT2-7B / 30B-A3B（Q4 18.2GB） | 太大 | Apache-2.0 | 只做"电脑端批处理"外挂，不进手机 |
| NLLB-200 / MADLAD-400 蒸馏版 | 0.6–1.3GB | CC-BY-NC / Apache | **不要**：小体积下中英质量明显退化，比 1.8B 专用模型差 |
| Marian / Opus-MT（ONNX Runtime Mobile） | ~0.1–0.3GB | MIT/Apache | 极限轻量档 B；编码器-解码器，无 prompt（`SmallMTPromptBuilder`）；`en→zh` 常需英文枢轴 |
| iOS `Translation` 框架（系统） | 0 | 系统 | 兜底 C；不可注入术语、质量不可控、语言包由系统下载 |
| Android ML Kit `translate`（经典） | 每语言 ~30MB | Google ToS | 兜底 C；59 语；非配对语走英文枢轴 |
| Android ML Kit GenAI（Gemini Nano） | 0（AICore 共享） | GenAI 附加条款 | ⚠️ **没有 Translate API**，只有 Summarization/Proofreading/Rewriting/ImageDescription/SpeechRecognition/**Prompt** → 想用 Nano 翻译只能拿 Prompt API 自己写指令，且机型白名单窄（Pixel 9–11、S24–S26、Xiaomi 15…） |
| MediaPipe LLM Inference API | — | Apache-2.0 | ⚠️ 官方标注**只维护不加新功能**，新代码走 **LiteRT-LM**（v0.16 起有 C API 预编译库，Kotlin 稳定、Swift 早期预览、含 Apple Foundation Models 适配器） |

## 4. 推理引擎选择

- **iOS / Android 统一用 llama.cpp（GGUF）**：唯一同时满足「支持 1.25-bit/2-bit 这类非常规量化 + 跨平台 + 可加载 LoRA + MIT 许可」的组合。代价：两端各自集成（xcframework / .so）。
- 想要 NPU/GPU 加速与更小内存：**MNN**（`wangjazz/Hunyuan-MT1.5-1.8B-MNN` 实测 1.01GB 整包）或 **LiteRT-LM**（安卓 GPU/NPU 后端成熟），但 1.25-bit 这种极限量化基本只在 llama.cpp 生态里现成可用 → **本项目按 llama.cpp 落地，MNN 作为性能优化分支**。
- 不要自己写 tokenizer：GGUF 内嵌 `tokenizer.chat_template`，直接喂 messages；只有导出异常时才用 `Prompt.as_chatml()` 兜底。

## 5. 许可证执行清单（上架前逐条勾）

1. App 内 `设置 → 开源许可` 页必须包含：llama.cpp(MIT)、Hy-MT2(Apache-2.0，含 NOTICE 与"Based on Tencent Hunyuan-MT"署名)、ML Kit/Google SDK 条款链接。
2. Apache-2.0 要求：保留版权与许可声明、标注修改（若你重量化/改了权重，要在 NOTICE 里写"本次对权重做了 X 量化"）。
3. 若走 TranslateGemma/Gemma：单独附 Gemma Terms of Use 全文或入口，且**不要在 App 里直连 gated 的 HF 链接**。
4. 自学习数据、术语表、TM：全部只存设备 → 隐私标签可写"不收集数据"（Apple 隐私营养标签 / Play Data Safety 表单同步）。
