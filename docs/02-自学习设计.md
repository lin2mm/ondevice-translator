# 02 · 自学习设计（四层，全本地，零训练成本）

## 0. 先把话说清楚

手机端"自学习"**不是**在手机上更新权重：
- 主力权重是 1.25-bit 稀疏三值量化（Sherry/SEQ），**不可训练**（无法反向传播）；
- 1.8B 全参 SFT 需要几十 GB 显存，QLoRA 也要 12–16GB 且要跑几十分钟；手机做不了。

真正能交付、也确实"越用越准"的是四层，按投入产出排序：

| 层 | 机制 | 生效时机 | 成本 | 已实现 |
|---|---|---|---|---|
| **L1 翻译记忆 TM** | 用户接受/编辑过的 `源句 → 译文` 入 SQLite；相似句以 few-shot 注入 prompt | 下一次遇到相似句，**即时** | 0（CPU <1ms） | ✅ `core/learn.py` |
| **L2 术语挖掘** | 从"机翻 vs 人改"的差异里统计共现，稳定对应自动进术语表待确认 | 累计 ≥2 次后 | 0 | ✅ |
| **L3 风格/个性化画像** | 统计用户在简繁、语气、人称、术语一致性上的偏好 → 落到 style / personalization 模板 | 即时（有开关） | 0 | 部分（统计位已有，UI 待接） |
| **L4 离线 LoRA（可选）** | 用户在自己电脑上用官方 `train/` 脚本练 adapter，转成 GGUF/LoRA 装回手机 | 重装后 | 需要一台带 GPU 的电脑 | 脚本位 `tools/train_lora.sh` |

## 1. L1 翻译记忆：为什么 few-shot 而不是 RAG

小模型对 3 条例句极其敏感，而且 Hy-MT2 官方就有 Terminology 模板（`X 翻译成 Y`），**例句块和术语块是同一种语法** → 不需要新训练就能被模型接受。工程要点（都在代码里）：

- 相似度：字符 3-gram Jaccard + **长度惩罚**（只共享一个短语的长句必须被压掉，否则会把整篇文拽偏）。
- 存 `src`（归一化，用于匹配）**和** `src_raw`（原文，用于渲染）：`norm()` 会小写化，若用它渲染例句，`iPhone`/`API`/`kPa` 这类大小写信息会被永久教会成错的。这是我实测踩到后修的（`tests/test_all.py::test_learn_injection_reaches_prompt`）。
- 打分：`edited`（用户改过）=1.0，机翻被原样采纳 =0.4；采纳犹豫 >4s 再加 0.3（他真读了）。召回排序 = 相似度×是否改过。
- 表容量默认 20000 行，超出按 `score/used/created` 淘汰 —— 手机上 SQLite 索引扫描 4000 条候选 <1ms，够用且可离线验证。
- **缓存一致性**：TM/术语表版本变了必须让译文缓存失效（`Translator._glossary_v/_learn_v` 进 key）。否则用户改了术语，界面上的旧译文会一直"看起来没生效"——这是这类产品最常见的差评来源。

## 2. L2 术语挖掘：只做统计，不做对齐

早期版本我按"逐字位置回溯源词"来挖术语，实测立刻产出 `("把超","configure")` 这种垃圾对，于是换成**跨句统计共现**：

```
对每个"用户新增的译文词 w"：
  支持集 idxs = {含 w 的新增的那些编辑}
  对源句 n-gram g：cover = |g 出现在 idxs| / |idxs|
                   bg    = (g 在总表出现次数 - cover 次数) / (总句数 - |idxs|)
  条件：cover ≥ min_support(2)、bg ≤ 0.5      # 在不相关句里也到处冒的 g 不是术语
  排序：cover · (1-bg) · (1 + 0.12·|g|)      # 长 n-gram 稍加奖励（更精确）
最后：长词优先，丢掉被更长候选包含的短 n-gram
```

为什么可信：要求"至少两句独立证据 + 不在无关句里乱冒"，把"一次改动学到怪术语"这条路堵死。代价是**要改 2–3 次才学会**，所以 UI 上必须写清"我看到你把 X 统一改成 Y，要固化吗？"（`pending_terms` → 一键确认 → `export_glossary_tsv` → 变 `enforce`）。

`_diff_fragments` 必须**词级** diff：字符级 SequenceMatcher 会把 `callback→webhook` 学成 `we`/`hoo`（这个 bug 被单测抓到过）。

## 3. L3：把"风格"变成可读的画像

- 从 TM 统计：句末是否加句号、是否用"您"、`iPad` 类品牌词是否被译、简/繁比 → 生成 3–5 条 `personalization` 规则，用户在设置里逐条开关。
- 规则进模型的方式就是官方 Personalization 模板（编号列表），**不写死在 system prompt**（Hy-MT2 无默认 system prompt）。
- 禁止静默改行为：任何自动学到的东西都要能在"设置 → 已学到 N 项"里看到、能一键删。

## 4. L4：想真正"改权重"的人（可选，不影响主流程）

1. 用户在电脑上 clone 官方仓库，用自带 `train/llama_factory_support/hy_dense_1_8b_lora_sft.yaml`；
2. 数据 = App 导出的 TM（`导出学习数据` 按钮 → jsonl：`{"messages":[{"role":"user","content":"将以下文本翻译为 英语…"}]}` + assistant = 用户定稿）；
3. QLoRA 8k 句 ≈ 单卡 24GB 1–2 小时（Colab 免费 T4 可跑 1.8B 的小 batch，慢但免费）；
4. 合并 → 转 GGUF（`convert-hf-to-gguf.py`，需给 hunyuan 架构加模板）→ 通过 `manifest` 的 `lora` 字段挂到 App（llama.cpp `--lora`）。
5. App 侧要做：adapter 与 base 权重**版本绑定**（manifest 里 `requires: base=hash…`），加载失败自动退回 base。

## 5. 数据与隐私（"自学习"必须是本地学习）

| 数据 | 存放 | 备份 | 出境 |
|---|---|---|---|
| TM / 术语 / 画像 | App 私有目录 SQLite（iOS `Application Support/Learn/`，Android `getDatabasePath`，且**排除**自动备份） | 用户自己的 iCloud/Drive（端到端加密导出 `.localmt.sqlite`） | 无服务器，不出境 |
| 原始输入文本 | 只在内存 + 可选历史（默认开，7 天滚动） | 同上 | 无 |
| 埋点 | 只记"档位/延迟/失败原因枚举"，**永不记文本** | — | 可选关闭 |

同步策略：**不自建服务器**（要永久免费就别建）。换机迁移用"用户自己的云盘里的一个文件"，冲突时按 `created` 合并，不做多端实时同步。

## 6. 怎么证明"自学习"真的有效（可量化，别自嗨）

准备 3 个域（技术博客、聊天、法律条款），每域 60 句中英对，跑 A/B：

| 指标 | 冷启动 | 允许"学习 20 句后"的目标 | 测法 |
|---|---|---|---|
| chrF++（vs 人工参考） | 基线 | **+1.5 分** | `tools/eval_zh_en.py`（sacrebleu） |
| 术语命中率（自定义 20 条术语） | 基线 | ≥95% | 译文子串检查（`Glossary.apply` 已返回违规） |
| 用户改动率（编辑距离/句长 >0.15 的句占比） | 基线 | **−30%** | 本地统计，不上传 |
| 数字/占位符错误 | — | **0**（硬红线） | `core/validate.py` 的 `num_mismatch/placeholder` |
| 首字延迟 | 真机基线 | 注入例句后 ≤ +15% | `tools/bench_mobile.py` |

学不动/学坏了的兜底：`已学到` 面板里逐条可删；`清空学习数据` 一键回到出厂；每次启动若发现"改动率反而上升"连续 3 天，自动降低 few-shot 注入条数（3→1）。
