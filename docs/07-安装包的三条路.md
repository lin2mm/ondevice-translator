# 07 · 安装包怎么来（三条路的真实成本表）

你要求的是：**模型打进包、一装就跑、不要任何额外操作**。这个目标本身完全能做到，
但它和"绕过苹果"是两件事。下面每一条我都标了**我能不能在这个工作区替你完成**。

| 路线 | 产物 | 首次可用需要几步 | 我能替你做完吗 |
|---|---|---|---|
| **iOS 原生（脚本）** | 直接装进你的 iPhone 15（`xcrun devicectl`） | 你在 Mac 上跑 1 条命令 | ❌ 做不到。沙箱是 Linux，无 Xcode/SDK/签名；iOS 的 .ipa 只能在 macOS 上编译并用你的身份签名 |
| **Android APK（CI 构建）** | Release 附件里的 `.apk`（模型已内置） | 浏览器下载 → 点开 → 允许未知来源 | ⚠️ 半能：我把工程 + workflow 写全，你只需推到 GitHub 点一次 Run（**不用装任何本地工具**） |
| **PWA（免安装）** | 一个 URL，"添加到主屏幕" | 3 步（推仓库 / 开 Pages / 加主屏幕） | ✅ 外壳代码已写好；但只能跑小模型，**质量不等于原生方案** |
| 在这个沙箱里编出 APK | — | — | ❌ 不做承诺：2GB 内存/2 核，编 llama.cpp + 1.6GB 产物你也没法从这里取走 |

## 你需要给我的不是"权限"，是这三样

这个环境**没有任何通往你电脑的通道**（我能执行的只有沙箱里的 shell）。所以要落地，需要你做的只有：

1. **iOS**：一台 Mac（借/租都行）+ 一个 Apple ID（**免费**即可真机安装，7 天重签）+ 数据线，
   然后跑：`./ios/install-on-iphone15.sh --model small`
   —— 它会自己下载权重、实测 sha256、生成 manifest、xcodegen、编译、签名、装机、启动。你不用打开 Xcode。
2. **Android**：把整个目录推到 GitHub，Actions 里点一次 Run，从 Release 下 `.apk`。零本地工具。
3. **PWA**：`./web/deploy-github-pages.sh <你的用户名> <repo>` → 开 Pages → 手机浏览器打开 → 添加到主屏幕。

付费只在两种情况下才需要：想让别人长期安装（Apple 99 USD/年、Play 一次性 25 USD）。
自用测试：**0 元**（免费 Apple ID 自签 7 天 + Android 侧载）。

## "模型打进包"的代价，签之前看清楚

- **iOS**：`.app` 里塞 462MB → Xcode 装机可行；但若你要上 App Store，需按 docs/05 改回"首包小 + 运行时下载"，
  因为大体积 + 无 ODR 会导致蜂窝下载/审核问题。另外 `Increased Memory Limit`（1133MB 档在 6GB 机器上的保险）
  是**付费账号专属 entitlement**，免费账号请用 `--model small`。
- **Android**：`assets/` 放 .gguf 必须 `noCompress`（否则 aapt 压缩后 mmap 直接失败），
  APK 1.6GB 只能侧载；Play 有包体上限，需 AAB + 安装时下载或 Play Asset Delivery（docs/05）。
- **两端共同**：包内模型无法热更新 → 换权重必须重装 App。想"零操作"就接受"换模型=换安装包"。

## 我在这个仓库里已备好的东西（可以直接被上面三条路用上）

| 文件 | 作用 |
|---|---|
| `ios/install-on-iphone15.sh` | Mac 上一条命令：下模型→实测 sha256→manifest→xcodegen→编译→签名→装机→启动；带 `--dry-run` 预演 |
| `ios/project.yml` + `ios/Sources/*.swift` | 阶段 1 只依赖系统 `Translation` 框架（可编译、零三方依赖）；阶段 2 在 `EngineFactory.swift` 一个 TODO 处插 llama |

| `tools/lint_platform_code.py` | 装机前的硬约束自查（16KB、mmap、明文 http、manifest 两端同源） |

## 别把试玩结果当成项目结论

PWA 用的是 600M 的 NLLB 蒸馏档，中英质量**明显低于** 462MB 的 Hy-MT2 专用模型；
用它判断"本地翻译能不能用"会得出错误结论。要判断可行性，只认这两个测法：
① Android：内置 Hy-MT2 的 APK 上真机；② iOS：PocketPal 加载同一个 GGUF（见 BUILD-ON-YOUR-MAC.md 的 A 节）。
