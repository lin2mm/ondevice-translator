# 08 · 你这边要做的操作（三条路，逐步可复制）

> 前提说清：**我这边没有任何通道能碰你的电脑或你的手机**，也不需要你的 Apple ID / GitHub 密码。
> 我能做的只有两件事：把命令写好、把你贴回来的**报错文字**读懂。整个流程里唯一需要"给"我的东西就是日志文本。

## 1. iPhone：Xcode + 免费 Apple ID 怎么设

**绝对不要把 Apple ID 密码给任何人（包括我、任何网站、任何"帮我签名"的机器人）。**
免费个人签名不需要证书文件、不需要 $99 开发者账号，也不需要把账号交给工具——Xcode 在你自己电脑上登录一次即可。

一次性准备（约 10 分钟 + 下载 Xcode 的时间）：

| 步 | 操作 | 备注 |
|---|---|---|
| 1 | App Store 装 **Xcode**，打开一次，同意协议、装完附加组件 | ~15GB，必须有，`xcodebuild` 没有它不存在 |
| 2 | Xcode → Settings → **Accounts** → `+` → 登录你的 Apple ID | 普通免费 ID 就行；记下 `Team` 那栏 10 位字符串（脚本能自动探测，探测不到再手填 `--team`） |
| 3 | 终端 `xcode-select --install`；`brew install xcodegen` | 没 brew 就 `xcode-select --install` 后先去 [brew.sh](https://brew.sh) |
| 4 | iPhone：设置 → 隐私与安全性 → **开发者模式** 打开 | iOS 16+ 必需；打开时手机会要求重启，重启后弹窗再确认一次 |
| 5 | 数据线连 Mac，手机上点 **"信任此电脑"** | 建议有线，`devicectl` 装 1.6GB 比无线快很多 |
| 6 | `cd ondevice-translator && ./ios/install-on-iphone15.sh --model small` | 一条命令：下权重 → 生成 manifest → xcodegen → 编译 → 装机 → 启动 |
| 7 | 手机上：设置 → 通用 → VPN 与设备管理 → **Developer App** → 信任 | 只做一次，第二次装不用重复 |

要点：
- `--model small` = 462MB 档。6GB 的 iPhone 15 上，`--model big`（1133MB）大概率被 jetsam 杀；
  而且免费签名拿不到 `increased-memory-limit` entitlement，**这条路不能靠调 entitlement 绕过内存上限**。
- 免费签名 **7 天过期**，过期后 App 打不开 → 重跑第 6 步即可；同时最多装 3 个自签 App。
- 想每天用/给别人用就只有 TestFlight（$99/年）。这是苹果的收费，不是我们的方案收费。

**没有 Mac 怎么办**：iOS 没有干净的路。Windows 上 AltStore/Sideloadly 自签属可行玩法，但我们的 App 有
ObjC++ 桥 + Metal + 大体积资源，这条路我**没有验证过**，不建议当主计划。真要双端，就借一台 Mac 半天。

## 2. Android：GitHub Actions 出 APK（你本机零工具链、零费用）

### 2.1 把代码送进 GitHub
1. 下载我打包好的源码：工作区根目录 **`ondevice-translator-src.zip`**（223KB，90 个文件，不含权重）
2. 解压 → 在 github.com 新建仓库，**选 Public**（公开仓库 Actions 免费额度是"不限时长"，私有是 2000 分钟/月；
   我们一次 CI 要 20-35 分钟且要下 1.6GB 权重，公开的更稳）
3. 上传方式二选一：
   - 网页：仓库页 → `uploading an existing file` → 把解压目录里的**内容**整个拖进去（`.github` 目录会一起进去，这是关键）→ Commit
   - 命令行（更保险，网页上传偶尔漏隐藏目录）：
     ```bash
     cd ondevice-translator
     git init -b main && git add -A && git commit -m "init: on-device zh-en translator"
     git remote add origin https://github.com/<你的用户名>/<仓库名>.git
     git push -u origin main
     ```
     `git push` 会让你登录：用浏览器授权或 Personal Access Token（Scope 勾 `repo`）都行，**不要用密码**。

### 2.2 触发流水线
仓库 → **Actions** → 左栏 `Android APK（模型内置，免本机工具链）` → **Run workflow** → 填：

| 输入 | 取值 | 说明 |
|---|---|---|
| `model` | `both` | 462MB + 1133MB 都打进包，方便你并排试（首包 ~1.6GB）；只想快点看到效果就 `small` |
| `native` | `true` | 编 llama.cpp → 真离线推理。`false` 只出"系统兜底版"（ML Kit，30MB/语言，不算本项目主引擎） |
| `llama_ref` | `v0.4.0` | 实测 `ggml-org/llama.cpp` 的 `releases/latest` = v0.4.0（2026-09-04 发布），别填 `b6900` 之类老写法 |

### 2.3 拿包 + 装
- 跑完点进那次 run → 页面**最底部**有 `apk-<编号>` 的 Release → 下 `app-debug.apk`
- 传到手机（微信/网盘/数据线都行）→ 点开 → 允许"未知来源/允许此应用"→ 安装
- **装机后第一件事：开飞行模式，翻一句。** 这才是"离线"的验收，而不是"能翻"。

### 2.4 失败时给我什么
Run workflow 页面里点红色那一步 → 展开日志 → **复制末尾 30-50 行**贴回来。
常见三种，我自己就能定位：
| 日志里出现 | 含义 | 处置 |
|---|---|---|
| `SDK location not found` / `ndk ... not found` | 镜像里 ANDROID_HOME 没接上 | 我加显式 `local.properties` 生成步骤 |
| `No space left on device` | 1.6GB 权重 + NDK 撑爆 runner | 把 `model` 改 `small` |
| `undefined symbol: llama_...` | llama.cpp v0.4.0 API 与 `llama_jni.cpp` 不一致 | 把报错的符号名贴回来，我按新版 API 改 |

## 3. 今天就能做的模型验收（PocketPal AI，不写一行代码）

目的：**在花 40 分钟等 CI 之前**，先确认 462MB 这档在你的 A16 上"能跑 + 够快"。跑不通，App 就不用做了。

1. App Store 搜 **PocketPal AI**（开源，作者 a-ghorbani；完全免费）
2. `Models` 标签 → `+` / **Add Custom Model** → Model URL 填：
   `https://huggingface.co/tencent/Hy-MT2-1.8B-1.25Bit-GGUF/resolve/main/Hy-MT2-1.8B-1.25Bit.gguf`
   若它要求 HF token：huggingface.co 免费注册 → Settings → Access Tokens → 建一个 **Read** 权限 token 粘进去
3. 下载完 → 该模型 **Edit / GGUF Metadata** → 把 **Context 改成 2048** 并保存
   （它默认照抄 GGUF 里的 `context_length=262144`，不改成必炸：光 KV 就要 34GB）
   其余：`threads=4`、`use_mmap=ON`、`gpu_layers=999`（被杀就改 0 走 CPU）
4. 采样：`temp 0.7 / top_p 0.8 / top_k 20 / rep_pen 1.05`
   （PocketPal 里先用权重内嵌的 0.8；正式包按 `core/prompt.py` 的 0.6，两条都跑一遍，谁好跟谁）
5. `Chats` 里选该模型，发这条（指令 + 待翻句必须同一条消息；中→英方向按模型卡**必须用中文指令**，
   语言名写「英语」——见 core/prompt.py 与 docs/06 风险 #10）：
   ```
   将以下文本翻译为 英语，注意只需要输出翻译后的结果，不要额外解释：

   本文所述方法已在三个生产环境中稳定运行十八个月，其间未发生重大故障；详见附录二的评估表。
   ```
6. 再发 2 条中英互译（引号嵌套 + 术语各一条），然后按下表判：

| 现象 | 结论 | 动作 |
|---|---|---|
| 报 `unknown architecture` / 不认 `hunyuan-dense` | PocketPal 的 llama.cpp 太老 | 只能验体积/速度，模板质量等我们的包 |
| 1.25bit 加载失败、Q4_K_M 正常 | 462MB 档在手机上不可用 | 把 docs 里所有 462MB 假设改成 1133MB，首包体积重算 |
| 切后台再回来白屏/被杀 | jetsam（6GB 内存） | 462MB + `ctx 1024`，并把"常驻"改成"用时加载" |
| ≥12 tok/s | 值得继续投 UI | 开工打包 |
| <8 tok/s | 这代硬件撑不住 1.8B | 换引擎：Opus-MT/Marian（B 档）优先，别硬撑 |
| 开头复读半句、停不下来 | 模板/token 不对 | 正常——PocketPal 拼的是自己的模板；见下面"已修的真 bug" |

## 4. 本轮顺手修掉的 4 个真 bug（都在双端引擎代码里，之前会导致"输出崩/停不下来"）

1. **特殊 token 的竖线必须是全角 U+FF5C，不是 ASCII 竖线。**
   实测依据：对真实 GGUF 做 Range 读，前 3MB 内 ASCII 形式 `<` + ASCII 竖线 + `hy` 出现 **0** 次，
   全角形式出现 **803** 次；`tokenizer_config.json` 的 bos/eos/pad 也全是全角。
   iOS 桥接层以前用片段拼成了 ASCII 形式 → 词表查不到 → 当普通文本。iOS/Android 两侧现在都用 `\uFF5C` 转义写死，
   源码保持纯 ASCII，任何编辑器/复制粘贴都不会把它"规范化"回去。
2. **iOS `renderedUser:` 的格式串只有 3 个占位符却传了 4 个参数** → assistant 头被静默丢掉，
   模型不知道该接着说话。已改 4 个占位符，并在注释里写明这个坑。
3. **Android `llama_jni.cpp` 用 `add_special=true` 自己又不拼 BOS 语义** → 双 BOS，首句概率性复读；
   同时它原来"不套模板"，靠 `llama_chat_apply_template` 读权重内嵌模板——但**权重里根本没有** `tokenizer.chat_template`
   （两个档都实测确认）→ 它会退回默认 ChatML。现在 native 侧自己按 jinja 展开拼，并 `add_special=false`。
4. **CI/构建配置的三处自相矛盾**：
   - `build.gradle.kts` 无条件 `excludes += "**/libllama.so"`，开了 native 会把刚编出来的库排掉 → 改成仅在 `!nativeOn` 时排；
   - `CMakeLists.txt` 里 llama 源码相对层级写成 4 层（指到 `android/vendor`）→ 改 5 层（仓库根）；
   - CI 原来要求"仓库里必须已提交 gradle wrapper jar"（我们没有）→ 改成 `gradle/actions/setup-gradle@v4` + 缺 wrapper 时现生成。

# 6. 手动处理 Xcode / macOS / 签名（不依赖我那个脚本时，全部要点都在这里）

## 6.1 先说"如何给你"：不给

我没有你电脑的通道，也不需要你的凭据。整个流程里唯一要给我的东西 = **报错文字**。
反过来说，下面这些永远不该出现在聊天里：Apple ID 密码、验证码、`*.p12` + 口令、App Store Connect API Key、GitHub token（贴 token 也只贴"已生成"这句话）。

## 6.2 三样东西各自要什么

| 东西 | 最低要求 | 不要做的事 |
|---|---|---|
| macOS | 能跑当前 Xcode 的版本（Apple Silicon 任意一台；二手 M1 Mac mini 是最便宜的入口） | 别用黑苹果当开发机：签名环节要真 iMessage/Apple ID 设备链，虚拟机/黑苹果经常过不了 |
| Xcode | App Store 最新版，装完 `sudo xcode-select -s /Applications/Xcode.app` | 别只装 Command Line Tools：`xcodebuild` 找不到 iphoneos SDK，`xcrun --sdk iphoneos --show-sdk-path` 会直接报错 |
| 签名 | **免费 Apple ID 就够**（Personal Team） | 不要为"自己装机测试"付 $99；也不要买"共享开发者账号"（苹果封号，且对方能看你的 bundle id/设备） |

命令行前置（一次性）：
```bash
xcode-select --install            # 命令行工具
brew install xcodegen cmake ninja # 工程生成 + 编 llama
sudo xcode-select -s /Applications/Xcode.app
xcrun --sdk iphoneos --show-sdk-path   # 有输出 = Xcode 装对了
```

## 6.3 纯手工建工程（GUI 路线，一步不漏）

脚本走的是 `xcodegen generate`；想用纯 GUI（或想看懂脚本在干什么）就照下面做。**每一行都是踩过坑的必填项**：

1. Xcode → File → New → Project → **iOS App**；Product Name `LocalMT`，Interface **SwiftUI**，Language Swift，最低支持 **iOS 18.0**
2. 把仓库里的 `ios/Sources`、`ios/Bridge`、`ios/Resources` 拖进工程导航栏 → 弹窗勾 **Copy items if needed** + Add to targets: `LocalMT`
   （`Resources/models/*.gguf` 也要在里面；确认它们在 target → Build Phases → **Copy Bundle Resources** 里，缺了就"装上没模型"）
3. target → Build Settings，逐条搜名字改：
   | 键 | 值 | 不这么写的后果 |
   |---|---|---|
   | `Objective-C Bridging Header` | `$(SRCROOT)/Bridge/LlamaBridge.h` | Swift 里 `LTLlamaBridge` 未定义 |
   | `C++ Language Dialect` | `GNU++17` | `.mm` 里 `<atomic>`/`std::string` 报错 |
   | `GCC_ENABLE_CPP_EXCEPTIONS` | `YES` | llama.cpp 抛异常 → 直接 crash，栈看不到 |
   | `GCC_ENABLE_CPP_RTTI` | `YES` | 同上（`dynamic_cast` 路径） |
   | `Framework Search Paths` | 追加 `$(SRCROOT)/Vendor` | `framework 'llama' not found` |
   | `Header Search Paths` | 追加 `$(SRCROOT)/Vendor/llama.xcframework/ios-arm64/Headers`，**Non-recursive** | `llama.h file not found` |
   | `Deployment Target` | 18.0 | 系统 `Translation` 框架（C 档兜底）进不来 |
   | `Enable User Script Sandboxing` | NO（工程有脚本时） | 脚本读不到仓库外层文件 |
4. target → General → **Frameworks, Libraries, and Embedded Content** → `+` → `Add Other… → Add Files…` → 选
   `ios/Vendor/llama.xcframework`，把它的 Embed 设成 **Do Not Embed**（静态库；Embed 了反而签名/启动都出问题）
5. target → **Signing & Capabilities**：
   - Team 选你的 **Personal Team**（显示为 "你的名字 (Personal Team)"）
   - Bundle Identifier：自签装机阶段**不要求全局唯一**（只有上架才查），但你自己的 App 想以后上 TestFlight 就用你域名反写，例如 `com.<你的名字>.localmt`；`com.apple.*` 一定别碰
   - **勾着 Automatically manage signing**，不要手动下 profile：免费账号的 profile 由 Xcode 自动生成，7 天有效
   - 不要加任何 capability（`increased-memory-limit` 是付费账号才有的 entitlement，个人账号加了会直接报 "provisioning profile doesn't include this capability"）
6. **先编引擎，再编 App**（这一步是我脚本刚补上的，缺它必失败）：
   ```bash
   ./tools/build_llama_ios.sh          # 产出 ios/Vendor/llama.xcframework，首次 ~6 分钟
   ```
7. 手机连数据线 → 解锁 → Xcode 顶部设备下拉选你的 iPhone → **Cmd+R**
   第一次 Xcode 会自己注册设备、生成 profile（看到 "Preparing <设备>… / Fetching developments..." 是正常的，可能几分钟）
8. 手机上：设置 → 通用 → **VPN 与设备管理** → Developer App → **信任** → 回桌面点开 App
9. iOS 16+ 还要：设置 → 隐私与安全性 → **开发者模式** → 打开（手机会要求重启一次）
10. 装机后第一件事：**开飞行模式翻一句**（这才叫离线验收；不是"能翻"）

## 6.4 免费签名的规则（会被这些卡住，不是 bug）

- **7 天过期**：App 图标还在，点开提示"无法打开/不可用" → 回 Xcode **Cmd+R 重签**即可，不用删重装、数据不丢
- **同时最多 3 个自签 App**；超了就删一个再签
- **最多 10 台设备/年**（Personal Team 也是这个数），每年 1 月重置
- 换 Apple ID = 全部重签；Family/工作账号别拿来干这个
- 想让别人装 / 想 90 天不过期 / 想 TestFlight → 只有 $99/年 付费账号；这跟"App 永久免费"不冲突（苹果收的是分发费，不收用户钱）

## 6.5 编译/装机报错 → 对号入座

| 报错原文（关键词） | 原因 | 处置 |
|---|---|---|
| `llama.h file not found` / `framework 'llama' not found` | 没编 xcframework，或 Header/Framework Search Paths 不对 | 跑 `./tools/build_llama_ios.sh`；核对第 6.3 步表格里的两个路径 |
| `No signing certificate "iOS Development" found` | Accounts 里没登录 / 网络被墙 / 刚 Sign Out | Xcode → Settings → Accounts → `+` Apple ID；重登一次 |
| `Provisioning profile ... doesn't include the device` | iPhone 没注册进 profile（或换了 UDID） | Window → Devices and Simulators → 选中设备 → 等 "connected"；再 Product → Clean → Cmd+R |
| `device is locked` / `pairing in progress` | 手机锁屏 / 没点"信任此电脑" | 解锁手机 + 信任弹窗，拔插一次数据线 |
| `A dependency on 'llama.xcframework' was not found` | 工程不在仓库旁边（xcodegen 用 `$(SRCROOT)`） | 把 `.xcodeproj` 放回 `ios/`，或直接 `cd ios && xcodegen generate` |
| `Increased Memory Limit ... doesn't include this capability` | 加了付费账号才有的 entitlement | 去掉该 capability，或者 ctx 降到 1024（本项目的 `--model small` 就是为 6GB 机器设计的） |
| 装完打开是系统翻译而不是本地模型 | `Resources/models` 空（没下权重就打包了） | App 内"关于"页看引擎那行；重跑 `--model small` |
| 启动后立刻被杀（无崩溃日志） | jetsam：462MB + 2048 ctx 的 KV 超了 6GB 预算 | ctx 1024、`gpu_layers` 0 先保稳，再看 tok/s |
| 冷启动很慢（>2s） | mmap 关掉了 / 权重被压缩打进包 | `use_mmap=true`；确认 `.gguf` 在 Copy Bundle Resources 而不是 "Compile Sources" |

## 6.6 手头确实没有 Mac 的话（诚实排序，不粉饰）

1. **借一台 Mac 半天**，或买二手 M1 Mac mini —— 唯一长期省心；签名必须在本机做
2. **云 Mac**（AWS EC2 Mac / Scaleway / MacinCloud）：技术上能编能签，但
   - **绝不要在你不控制的机器上登录你的 Apple ID**：那台机器就成了你的"受信任设备"，能看到设备列表；用完立刻 Settings → Accounts → Sign Out，并在 appleid.apple.com 移除该设备
   - AWS EC2 Mac 有 **24 小时最小占用**（约 $1.2/hr，一次约 $30），只适合已有 Mac 环境的人
   - 云机器上没有你的 iPhone，`devicectl install` 用不了 → 只能产出 `.ipa`，还得回到本地签名流程。**所以云 Mac 对你这个目标基本没用**
3. **先只做 Android 侧验收**：462MB 档的 tok/s、内存峰值、模板正确性在 Android 上测出来的结论，
   90% 可以直接搬给 iOS（同一族 ARM 核 + 同一套 llama.cpp）；iOS 那边只额外要验 Metal 与 jetsam。
   这条是**最省事的顺序**，也是我建议你现在走的一条：先点 CI 出 APK，把数字拿到，再决定要不要为 iOS 折腾一台 Mac。
